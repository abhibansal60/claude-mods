# Audit of the claude-mods plugins, 2026-10-24

Each mod was checked against the plugin format of the installed Claude Code (2.1.309). The sources were the plugin-authoring skill's `reference.md` and the `claude-code.d.ts` that build writes. The audit looked for broken manifests, deprecated fields, hooks that can hang or slow every tool call, shell injection through tool input, and missing error handling.

## How it was checked

| Check | Command | Result on `main` (d1e45d9) |
|---|---|---|
| Manifests and hooks modules | `claude plugin validate ./<mod>` and `claude plugin validate .` | All 5 mods and the marketplace pass. The only warning is `ICON_MISSING`, from the plugin-directory checks, which do not affect the result |
| Tests | `claude plugin test ./<mod>` | 5 pass, 0 fail, 1 per mod, all on `hooks/parse.ts` only |
| Types | `tsc` 5.9 strict, with the tsconfig from the types header, kept outside the repo | 0 errors in all 5 |
| Install from GitHub | README's Install block run verbatim in a throwaway `CLAUDE_CONFIG_DIR` | All 5 install. `claude -p --debug` shows each `hooks module <mod>@claude-mods loaded` and `plugin.register … admitted` |

## Format

Nothing is broken or deprecated. All five mods use the current function-hooks format: `hooks/hooks.json` with `{ "modules": ["./register.tsx"] }`, a hooks module exporting `register: Register`, and `types/index.d.ts` contracts named in `plugin.json` that validate against every `$.state` key used. No mod uses command hooks (`hooks.json` `command` entries) or any field the validator flags.

## Shell injection

**None is possible.** Every host command goes through `$.process.run(argv)`, which runs an argument vector with no shell. Tool input reaches an argv in one place only: ship-state's `git -C <dir> rev-parse`. There `<dir>` is rebuilt as `$HOME/code/<[\w.-]+>`, so it can never start with `-` or carry shell syntax. The worst case is `~/code/..`, which is a harmless `git -C ~`. Two other inputs are trusted local output: herdr-fleet's `herdr agent focus <pane>` and the `tail <log>` path come from `herdr agent list`. One string went into a URL: ship-state's PyPI project name, read from a repo's `pyproject.toml`. The host stayed `pypi.org`, and the name is now URL-encoded (#6).

## Findings, by severity

Hook budget, as background: a hook has 10 s of its own time, but `$` calls (`$.process.run`, `$.state.*`, `$.http.fetch`) do not count against it. A `tool.call` hook that awaits a spawn therefore holds the tool call until that spawn's own timeout (30 s by default), and the budget does not cut it short.

| # | Severity | Mod | Finding | Status |
|---|---|---|---|---|
| 1 | High | browser-guard | **The guard fails open when the pairing question is dismissed.** `$.ui.ask` rejects on Esc and under `-p`. The rejection threw out of the `tool.call` hook, the engine skipped the hook (it had no `.catch`), and the unpaired Chrome action ran. | Fixed in #4 |
| 2 | High | herdr-fleet | **The kill guard has gaps.** `herdr session stop`, `herdr pane close $(herdr pane current …)`, ``herdr pane close `…` `` and `P=<me>; herdr pane close "$P"` all closed this session's own pane without a deny. | Fixed in #5 |
| 3 | Medium | ship-state | **A tool result is held for a git lookup.** After `next`, the `tool.call` hook awaited `track()`, which spawns `git rev-parse` (20 s timeout) for each new folder a Read/Edit/Bash names. On a slow disk or a hung git, the result reached the model up to 20 s late. | Fixed in #6 |
| 4 | Medium | ship-state | **PyPI false alarms.** A repo with a `pyproject.toml` that was never published (404), or a machine offline, read as live `?`. That counted as unshipped, so the row stayed yellow and every answer saying "done" toasted "not shipped". | Fixed in #6 |
| 5 | Medium | all | **Tests never touched the hooks modules.** Only the parsers were tested, so a broken `register`, matcher or tree passed CI. | Smoke tests in #3 |
| 6 | Low | ship-state | `session.start` read `$PWD`, the launching process's variable, not the session's `e.cwd`. Where a host does not set `PWD`, the session folder was never tracked. T3 sets it correctly today. | Fixed in #6 |
| 7 | Low | herdr-fleet | `refresh` had no in-flight guard. A hung `herdr agent list` stacked a new spawn every 20 s, and overlapping runs could toast "needs you" twice. | Fixed in #5 |
| 8 | Low | on-me | The matcher-less `tool.call` hook awaited a `$.state` read and write before `next` on every tool call of the main loop. | Fixed in #7 |
| 9 | Low | browser-guard | `$.tool.call(list_connected_browsers)` passes through the permission check and its dialog, and through every other plugin's `tool.call` hooks (on-me shows it as the current tool). `$.mcp.call` has neither. Not changed, because the switch can't be verified without a signed-in Chrome. | On the docket (#8) |
| 10 | Low | README | "Update later with `claude plugin marketplace update claude-mods`" only refreshes the catalog. A plugin installed from a GitHub marketplace runs its install-time copy until `claude plugin update <mod>@claude-mods`. | Fixed in this PR |
| 11 | Low | README | Said every mod has a `types/index.d.ts`, but browser-guard has none. It also never said that `tsc -p ./<mod>` needs the `.claude-plugin/types/` folder, which only a `--plugin-dir` session writes. | Fixed in this PR |
| 12 | Info | herdr-fleet, twin-meter, ship-state, on-me | `gating hook without .catch` on `tool.call`. For twin-meter, ship-state and on-me the hook is not a guard: it only watches the call or passes it on, so a failure correctly lets the call run. herdr-fleet's guard is pure regex over env values and cannot realistically throw. A fail-closed `.catch` there would block every Bash call if it ever did. | Left as is |
| 13 | Info | herdr-fleet | The kill guard is still best effort: `herdr api …` socket calls, `kill <pid>`, and `herdr worktree remove` of this pane's worktree are not caught. `$.fs.stat` cannot help with these, because the target is a herdr id, not a path. | Documented |
| 14 | Info | twin-meter | Every session runs `cswap list` every 2 min. With 6 herdr sessions that is 3 spawns a minute. Overlapping refreshes (a timer plus a `cswap` Bash call) are not deduplicated, but they only write the same value twice. No fix is clear enough to ship. | Left as is |
| 15 | Info | ship-state | `CLAIMS_DONE` matches "done" anywhere in an answer, and a branch with no upstream counts as unshipped. Both are deliberate (the toast is the point), but they make the toast frequent. | Left as is |
| 16 | Info | CI | CI installs the latest `@anthropic-ai/claude-code` unpinned. The plugin API is "early access" and moves between releases, so CI can go red with no change here. That is also the signal users on latest would want. CI does not type-check: no CLI command writes `claude-code.d.ts`, so the `tsconfig.json` `extends` is missing on a runner. | Left as is |
| 17 | Info | all | No per-mod README. The root README's table covers each mod. Every mod is missing an icon (a plugin-directory warning only). | Left as is |
